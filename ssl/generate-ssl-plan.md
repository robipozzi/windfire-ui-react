# Rework `windfire-ui-react/ssl/generate-ssl.sh` to issue CA-signed server certs

## Context

[generate-ssl.sh](/Users/robertopozzi/dev/windfire-ui-react/ssl/generate-ssl.sh) currently
produces a **fully self-signed** cert/key pair (`openssl req -x509 ... -subj "/CN=localhost"`),
hardcoded to `localhost` with no way to target the production host or plug into the Windfire PKI.
The sibling repo `windfire-security` already established that PKI: `ssl/createRootCA.sh`
generates a self-signed **Windfire Root CA** and installs it at
`$HOME/opt/windfire/ssl/truststore/WindfireRootCA.crt` (cert) and
`$HOME/opt/windfire/ssl/keystore/WindfireRootCA.key` (key, AES-256 encrypted), and
`ssl/generateServerCert.sh` issues per-host leaf certs signed by that CA using per-environment
SAN config files (`openssl_config_localhost.ext` / `openssl_config_raspberry.ext`).

Confirmed on disk: `~/opt/windfire/ssl/truststore/WindfireRootCA.crt` and
`~/opt/windfire/ssl/keystore/WindfireRootCA.key` already exist (generated by `createRootCA.sh`).

Confirmed from [server.js](/Users/robertopozzi/dev/windfire-ui-react/server.js),
[start.sh](/Users/robertopozzi/dev/windfire-ui-react/start.sh) and `.env`: the app's production
deployment host is **`raspberry02`** (not `raspberry01`, which is the separate Keycloak host used
by `windfire-security`'s own raspberry cert) — so the "raspberry" environment here must use
`raspberry02` as CN/SAN, distinct from the sibling repo's raspberry config.

`start.sh` invokes `bash ssl/generate-ssl.sh` **with no arguments** whenever the default
cert/key files are missing, as part of its non-interactive production build flow. The rewrite
must keep that zero-argument invocation working (default environment = `localhost`, default
filenames unchanged) so `start.sh` needs no changes.

Goal: rework the script so it issues a proper leaf certificate signed by the Windfire Root CA,
selectable by environment (`localhost` default / `raspberry`), with configurable cert/key/CA
filenames that keep their current safe defaults, output still written next to the script.

## Design

### New files in `windfire-ui-react/ssl/`

Two small SAN config files, mirroring (but not copying) the pattern in `windfire-security/ssl/`,
adapted to this repo's actual host:

- `openssl_config_localhost.ext`:
  ```
  basicConstraints = CA:FALSE
  keyUsage = digitalSignature, keyEncipherment
  extendedKeyUsage = serverAuth
  subjectAltName = @alt_names

  [alt_names]
  DNS.1 = localhost
  IP.1 = 127.0.0.1
  ```
- `openssl_config_raspberry.ext`: same header, `[alt_names]` → `DNS.1 = raspberry02`

These are config, not secrets — not covered by the existing `.gitignore` SSL exclusions
(`ssl/*.pem`, `*.key`, `*.crt`, `*.cer`), so they get committed like their sibling-repo
counterparts.

### Rewritten `generate-ssl.sh`

Keep sourcing `commons.sh` for colors (`CYAN`/`GREEN`/`RED`/`WHITE`/`NC`/`BOLD`). Structure,
mirroring the `parse_args`/case-based flag style used in
`windfire-security/server/start-auth-server.sh`:

- **Flags** (all optional, all with safe defaults — satisfies "allow to choose... safely
  default"):
  - `-e, --env <localhost|raspberry>` — default `localhost`
  - `-c, --cert-name <file>` — default `windfire-cert.pem`
  - `-k, --key-name <file>` — default `windfire-key.pem`
  - `-a, --ca-name <file>` — default `WindfireRootCA.crt`
  - `-h, --help`
  - Unknown flag → error + usage, exit 1 (matches sibling convention).

- **Path resolution**:
  - `CERT_FILE="$SCRIPT_DIR/$CERT_NAME"`, `KEY_FILE="$SCRIPT_DIR/$KEY_NAME"` — same directory as
    the script (req. 3), same default basenames as today (req. 2, keeps `start.sh`'s existence
    check and `.env` defaults valid).
  - `ROOT_CA_TRUSTSTORE_DIR="$HOME/opt/windfire/ssl/truststore"`,
    `ROOT_CA_KEYSTORE_DIR="$HOME/opt/windfire/ssl/keystore"` (verified real paths).
  - `ROOT_CA_CERT_PATH="$ROOT_CA_TRUSTSTORE_DIR/$CA_NAME"`; the CA private key name is derived
    from `$CA_NAME` by swapping a trailing `.crt` for `.key` (so the default resolves to
    `WindfireRootCA.key`, matching `createRootCA.sh`'s fixed pairing) →
    `ROOT_CA_KEY_PATH="$ROOT_CA_KEYSTORE_DIR/$ROOT_CA_KEY_NAME"`.
  - Env → `COMMON_NAME` + SAN ext file: `localhost` → CN `localhost` +
    `openssl_config_localhost.ext`; `raspberry` → CN `raspberry02` +
    `openssl_config_raspberry.ext`. Invalid `--env` value → error listing valid options, exit 1.

- **Preflight checks** (fail fast with clear messages, same tone as
  `generateServerCert.sh`'s Root CA check):
  - `openssl` on PATH (kept from current script).
  - If `$CERT_FILE` and `$KEY_FILE` already exist → print their paths and exit 0, unchanged
    idempotent behavior (delete-to-regenerate).
  - If `$ROOT_CA_CERT_PATH` or `$ROOT_CA_KEY_PATH` is missing → error telling the user to run
    `windfire-security/ssl/createRootCA.sh` first, exit 1.
  - If the resolved SAN ext file is missing → error, exit 1 (defensive; ships in-repo so normally
    always present).

- **Generation** (replaces the single `openssl req -x509` call):
  1. `openssl genrsa -out "$KEY_FILE" 4096` — keeps the 4096-bit key.
  2. `openssl req -new -key "$KEY_FILE" -out "$CSR_FILE" -subj "/C=IT/ST=Lombardia/L=Milano/O=Windfire/OU=Windfire UI/CN=$COMMON_NAME"`
     — `$CSR_FILE` via `mktemp`, cleaned up with a `trap ... EXIT` so it's removed on success
     *and* on failure.
  3. `openssl x509 -req -in "$CSR_FILE" -CA "$ROOT_CA_CERT_PATH" -CAkey "$ROOT_CA_KEY_PATH" -CAcreateserial -out "$CERT_FILE" -days 365 -sha256 -extfile "$EXT_FILE"`
     — signs with the Windfire Root CA (req. 4). Since `createRootCA.sh` encrypts the CA key
     with AES-256, openssl will interactively prompt for its passphrase here — expected, not an
     error path.
  4. On failure of steps 1–3: clean up any partial `$CERT_FILE`/`$KEY_FILE`, print an error, exit
     1 (mirrors `generateServerCert.sh`'s failure cleanup).
  5. `chmod 600 "$KEY_FILE"` (kept from current script).

- **Success output**: same style as today (`${GREEN}==> ...`), extended to also print the
  environment, CN/SAN used, and which Root CA signed the cert — plus a one-line note that the
  Root CA must be trusted by the client/browser (already documented for Keycloak's CA in this
  repo's README) since it isn't in the system trust store by default.

## Verification

1. `bash ssl/generate-ssl.sh -h` — usage prints, exits 0.
2. `bash ssl/generate-ssl.sh` (no args, both output files absent) — regenerates
   `windfire-cert.pem`/`windfire-key.pem` for `localhost`, prompting once for the Root CA
   passphrase; confirm exit 0 and `chmod 600` on the key.
3. `openssl verify -CAfile ~/opt/windfire/ssl/truststore/WindfireRootCA.crt ssl/windfire-cert.pem`
   → `OK`.
4. `openssl x509 -in ssl/windfire-cert.pem -noout -text | grep -A2 "Subject Alternative Name"` →
   shows `DNS:localhost, IP Address:127.0.0.1`.
5. `bash ssl/generate-ssl.sh -e raspberry -c raspberry-cert.pem -k raspberry-key.pem` → new files
   created (existing `windfire-*` files untouched since names differ); SAN check shows
   `DNS:raspberry02`.
6. Re-run step 2 unchanged → script detects existing files and exits 0 without prompting (no
   Root CA passphrase asked), confirming idempotent skip still works.
7. Temporarily rename `~/opt/windfire/ssl/truststore/WindfireRootCA.crt` and re-run with fresh
   filenames → script fails fast with the "run createRootCA.sh first" message, exit 1; restore
   the file afterward.
8. `./start.sh` (no cached certs) — confirm it still auto-generates via the script with no
   argument changes needed, and the production HTTPS server starts against the new cert.
